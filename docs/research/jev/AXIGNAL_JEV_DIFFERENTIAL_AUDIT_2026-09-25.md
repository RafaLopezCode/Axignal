## Summary

Phase A justifies the P0-JEV-03 finding: an evidence-support question cannot be evaluated from a candidate label and evidence identifiers when neither the claim proposition nor the referenced passage is present. AXIGNAL’s internal golden-case record stores semantic text separately from the `state` sent to the evaluator. The live run’s `0.20` is therefore observed accuracy under an insufficient request state; claim-evidence accuracy is **not established**. PR #14’s post-run audit reproduces the exact state fingerprint and documents this limit.

This is a defect in the research input/interpretation boundary, not evidence that Jev itself failed on a valid claim-support task. It does not show that every family is equally affected: entity alignment lacks a pair of records; relationship questions lack relationship proposition and semantic evidence; all questions share one generic state contract. Existing AXIGNAL authority boundaries remain appropriately strong. Keep the accepted P0-JEV-01/02 history; reconcile by a new governed spec/ADR before any new live pilot.

## P0-JEV-03 forensic reconciliation

The published result is internally described as `OBSERVED_ACCURACY_UNDER_P0_JEV_03_STATE=0.20`, and `JEV_CLAIM_EVIDENCE_ACCURACY=NOT_ESTABLISHED`. PR #14’s forensic diff states that, for each provider request, the adapter sent compiled `case["state"]`; the separate case `evidence` array was not attached. CES-01’s evidence entry says “direct record supports claim,” but its state only contains `candidate`, `evidence_ids`, `temporal_context`, `provenance`, and `known_unknowns`. No machine-readable claim exists. CES-07 has empty evidence IDs. The `minimal` transform removes temporal context and provenance, leaving candidate and IDs; it does not remove claim/passage because those never existed in the source state. Fingerprints reconstructed from unchanged data match the result artifact (PR #14 forensic table and accompanying text).

**Independent conclusion: `CLAIM_EVIDENCE_STATE_SUFFICIENCY=STRUCTURALLY_INSUFFICIENT`.** A claim-support judgment requires the proposition and semantic evidence content to be judged. An identifier is a retrieval key, not that content. This is supported by Phase A's official state definition and official citation-check recipe, which sends claim and section (O2/O12), and by repository payload inspection. It is not a claim about Jev performance with sufficient input.

## Architecture and lab cross-audit

- **State Compiler:** canonicalizes JSON and fingerprints payload deterministically; rejects a few secret/volatile keys and invalid JSON values. It does not resolve evidence IDs, enforce family-specific fields, tie required paths to a question, distinguish absent from explicitly unknown in a formal schema, or determine semantic answerability. Current P0-JEV-03 state actually omits claim and evidence; compiler preserves only what it receives. It neither loses the separate evidence array nor can preserve content never passed to it. Generic type/shape validation is not sufficient.
- **Decision Composer:** raw typed judgment and experimental composition are distinct. Relationship policy explicitly marks thresholds experimental and `canonical_authority=false`; no accidental canonical authority transfer found. Its neutral `0.5` transformations are experiment comparators only, not a supported production threshold. Unknown/missing/malformed sets become unresolved. Keep evidence admission separate.
- **Decision Laboratory:** controlled definitions, locks, fixed variants, budgets, repeatability/model-comparison types, offline replay, deterministic metrics/outcome evaluation, and operational failure classification are present. Missing control: an answerability/preflight validity check before interpreting a model-quality metric. It must separately capture case/golden invalidity, state sufficiency, question validity, primitive compatibility, provider response, composition and evaluator behavior. Request-byte budgets are not token or billed-cost evidence. Synthetic cases establish expected invariant behavior, not Jev quality.
- **Golden Corpus:** 42 synthetic cases (14 each family) with synthetic evidence text, references, source groups, expected labels and construction provenance. It is useful as a contract corpus; evidence text is not nested into sent state. Labels are synthetic construction, not independent real-world truth. Some `NO_EXPECTED_SINGLE_ANSWER` / contradictory cases have null labels and require metric-aware exclusion/handling.
- **Experiment plans:** claim wording changes instructions only and holds state fixed; state ablation deletes both time and provenance; relationship compound-vs-atomic changes question set and has a policy mapping. Plans use five-case samples, one repetition, no predeclared minimum effect and no empirical calibration. They are protocol skeletons, not sufficient live validation.
- **Metrics/outcome/replay:** deterministic outputs and offline replay support reproducibility; exact accuracy can conceal class composition and sample size, and no multi-class calibration metric is approved. PR #14 appropriately calls calibration unvalidated and invoice cost unknown. Add answerable denominator, abstention/coverage, class metrics and confidence calibration before claims.
- **Pricing:** published token rate and arithmetic estimate do not equal invoice cost. Missing usage stays unknown per P0-JEV-02. Confirm quote/usage at execution time without embedding secrets.
