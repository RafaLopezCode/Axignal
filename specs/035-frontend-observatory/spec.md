## User Scenarios & Testing
### User Story 1 - Discover an observing economic brain (Priority: P1)
A visitor follows a spatial, illustrated narrative, manipulates a small example and enters the same observation language in the product.
**Why this priority**: comprehension precedes conversion; a memorable moment must teach what observation does.
**Independent Test**: open landing, explore the lens, read how attention grows over time, use the demo, open Panorama.
**Acceptance Scenarios**:
1. Given a new visitor, when following the page, then what AXIGNAL is, how to start, accumulated understanding, time, use cases, demonstration and subscription logic appear in that order.
2. Given reduced motion or keyboard input, when exploring, then the same meaning and actions remain available without obligatory animation.
3. Given illustrative information, when inspecting a claim, then its demo status remains explicit; prices or capabilities are not fabricated as commercial commitments.

### User Story 2 - Understand a contextual signal (Priority: P1)
A subscriber moves from today's material signals through family context, explanation, reasoning and evidence, preserving organization and time.
**Why this priority**: this is the principal human value of AXIGNAL.
**Independent Test**: select a family, inspect one signal and its source, change time, navigate back and switch organization.
**Acceptance Scenarios**:
1. Given Panorama, when choosing a family, then primary attention changes while other families remain discoverable and the focus is reversible.
2. Given a potential result, when opening explanation/evidence, then potentiality, derivation, temporal limits and missing knowledge remain visible.
3. Given a past date, when moving the global timeline, then every signal and summary uses that snapshot; future information is unavailable.
4. Given mobile, when completing the same journey, then readable narrative, evidence and AXENT remain accessible without a compressed desktop canvas.

### User Story 3 - Investigate with governed AXENT (Priority: P1)
A person asks a contextual question and receives grounded text with controlled semantic components.
**Independent Test**: ask about the active signal, view the registered component, switch context while streaming and retry an error.
**Acceptance Scenarios**:
1. Given a contextual question, when a composition is returned, then only registered keys and known references render; evidence/state cannot be supplied by the model.
2. Given changed organization/time, when an earlier response arrives, then it is not rendered in the new context.
3. Given no provider authority, when using the local demonstration, then AXENT explicitly identifies its deterministic example mode and never claims live research.

### User Story 4 - Inspect privileged operations (Priority: P2)
An operator explores a clearly private Admin shell, inspects operational read models and previews governed actions.
**Independent Test**: open Admin, change domains, inspect records and preview a sensitive action.
**Acceptance Scenarios**:
1. Given Admin demonstration, when browsing, then private illustrative operations are visibly separated from economic truth.
2. Given a requested real write, when no authorized operational session exists, then the server denies it; role preview cannot authorize anything.
3. Given an operational action, when inspecting, then owning service, scope, authority requirement and impact are reviewable.

### User Story 5 - Experience one coherent accessible system (Priority: P2)
Landing, subscriber and Admin use the same official identity, component grammar and recovery states.
**Independent Test**: inspect design system, empty/unknown/unavailable/error/loading samples, ES/EN, keyboard and narrow viewports.
**Acceptance Scenarios**:
1. Given official assets, when rendered, then exact canonical derivatives are used without tracing or replacing the wordmark/isotype.
2. Given any failure or missing knowledge, then recovery is clear and UNKNOWN is never displayed as false.
3. Given focus navigation, then focus is visible, dialogs return focus, and spatial information has a textual alternative.

### Edge Cases
Malformed plan; unknown reference; duplicate items; stale context revision; unsupported dates; empty observation; network failure; aborted stream; no privilege; long copy; narrow viewport; reduced motion; missing history; source contradiction; potential vs observed; new detection vs event time.

## Requirements
### Functional Requirements
- **FR-001**: Deliver running Landing, Panorama, AXENT, Timeline, Admin and Design System in an isolated app/worktree.
- **FR-002**: Preserve exact official brand, fixed font families, observer consistency, luminous muted palette, soft borders and restrained Bic annotations; no realistic imagery.
- **FR-003**: Landing must teach with spatial continuity, interactive observation and accessible purposeful motion.
- **FR-004**: Subscriber must implement material Today, ten semantic families, direct cognitive depth, stable navigation, organizations/attention, and independently inspectable evidence.
- **FR-005**: Global time must reproject all visible knowledge; missing or future information remains unavailable.
- **FR-006**: UI must visibly retain epistemic state, provenance, observed/event/detected dates and derivation, without converting inference into observation or UNKNOWN into FALSE.
- **FR-007**: Generative UI must accept only a bounded typed plan with registered keys, authorized known reference IDs and matching context revision. Layout authority stays deterministic.
- **FR-008**: Use the current Vercel AI SDK UI transport and message/tool-part contract; no arbitrary generated HTML/JSX or direct canonical-write tools.
- **FR-009**: AXENT context/thread must reset safely on organization/time changes, offer stop/retry and clearly identify unavailable live cognition.
- **FR-010**: Admin must provide navigable operational domains, contextual detail and action previews, while writes fail closed without existing privileged service authority.
- **FR-011**: Provide responsive ES/EN UX, keyboard interaction, visible focus, reduced motion, descriptive accessible names and non-graph reading paths.
- **FR-012**: Provide loading, empty, unknown, unavailable and error states with honest recovery and no simulated observation progress.
- **FR-013**: Reuse canonical backend unchanged. All fixture economics are FIXTURE_ONLY. Any future live bridge requires explicit existing authorization and canonical projection mapping.
- **FR-014**: Complete deterministic repository gates, frontend build/contract validation and real browser QA; report human visual acceptance as pending rather than inferred.
### Key Entities
Organization (economic subject); Focus (private persistent attention); AXIGLAND (shared governed memory); Projection (scoped human view); Signal (attention-worthy cognitive output); EvidenceTrace (stored basis); TimelineSnapshot (as-of view); AXENTContext (scope/revision); CompositionPlan (presentation only); AdminReadModel (private operations).

## Success Criteria
### Measurable Outcomes
- **SC-001**: All five user journeys run locally in a browser without uncaught runtime errors.
- **SC-002**: All material sample claims expose epistemic state and evidence in at most two actions.
- **SC-003**: Unauthorized reference, stale revision, unknown component and malformed plan are rejected by deterministic tests.
- **SC-004**: Desktop and 390px mobile support the principal reading/evidence/AXENT path with no horizontal document overflow; keyboard can access primary actions.
- **SC-005**: Exact source hashes of brand derivatives are recorded; no required validation depends on LLM/network output.
- **SC-006**: Motion respects system preference; every interactive scene has a usable static equivalent.
- **SC-007**: Build and repository gates are reported from actual execution. Retention/admirability remain human/post-launch outcomes, not fabricated measurements.

## Assumptions
- EXPLORE mode: separate running app, accepted existing surfaces and Golden Master are not silently replaced.
- Local demo is valuable for complete interaction review; production data/provider/admin authentication must come from owning services rather than invented frontend authority.
- No pricing values or plan entitlements are invented; subscription presentation explains allocation and offers a preview.
- No canonical Python module is modified by this feature.
