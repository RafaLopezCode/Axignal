# EB-04 — First Economic Vertical E2E

**Status:** IMPLEMENTATION SLICE  
**Authority:** MASTER → Constitution → ADRs → Economic Brain Execution Roadmap  
**Roadmap slice:** EB-04

## Purpose

Prove that AXIGNAL can compose already-governed infrastructure into one reproducible economic reasoning chain from authorized source material to Human-First output without promoting model judgment to canonical truth.

## Reference case

Synthetic, AXIGNAL-authored, rights-cleared industrial refrigeration case:

- canonical organization: Arbor Cooling;
- observed capability from its authorized source;
- independent Harbor Storage project/need source;
- no observed commercial relationship;
- bounded structured evaluator is deterministic fixture only.

The target product result is a **POTENTIAL / WARRANTED_ATTENTION** opportunity when all core dimensions are answerable and aligned, or explicit **UNKNOWN / INVESTIGATE** otherwise.

## Required chain

1. Source Registry authorization precedes payload access.
2. Source acquisition crosses the governed source policy boundary.
3. HTML representation preserves visible material and exact spans.
4. Semantic extraction yields grounded candidates, never canonical truth.
5. Canonical organization mention is resolved through governed identity binding.
6. Capability may become FAXT only through EvidenceAdmission.
7. Independent need/event remains DECLARED unless separately admitted.
8. RichSubjectState preserves source/time/currentness/rights/extraction lineage.
9. Applicability and answerability are evaluated per dimension.
10. Structured evaluator remains replaceable and non-authoritative.
11. Python composes POTENTIAL, UNKNOWN, INVESTIGATE or WARRANTED_ATTENTION.
12. Explainable Basis and Human Output preserve exact evidence refs and spans.
13. Source, semantic and structured-evaluator dispatches cross GovernedExecutionController.
14. Attempts retain elapsed time, usage counters and explicit known/UNKNOWN cost.
15. Replay references reproduce the same semantic output from the same authorized inputs.

## Invariants

- CLAIM != WRITE
- OBSERVED != POTENTIAL
- JEV/MODEL JUDGMENT != TRUTH
- POTENTIAL != OBSERVED RELATIONSHIP
- UNKNOWN != FALSE
- RETRIEVED/EXTRACTED != CANONICAL
- SOURCE AUTHORIZED != EVIDENCE ADMITTED
- IDENTITY BOUND != CANONICAL TRUTH
- COST UNKNOWN != ZERO
- Human Output may compress presentation but not invent evidence.

## Exit criteria

- One deterministic authorized run reaches Human Output through the full reference chain.
- Capability is OBSERVED only after EvidenceAdmission; project need remains DECLARED.
- All six reference dimensions produce a TypedJudgmentVector.
- Aligned case produces POTENTIAL + WARRANTED_ATTENTION.
- Missing material context produces UNKNOWN + INVESTIGATE.
- Evaluator outage degrades safely and preserves evidence/attempt accounting.
- Material contradiction prevents positive presentation.
- Source budget rejection happens before the blocked fetch.
- Same inputs reproduce the same semantic output/replay refs.
- Exact support spans are present in Human Output.
- No observed relationship or sale probability is created.
- Full deterministic repository gates pass before integration.

## Out of scope

- JEV or Luna live provider use (EB-05).
- autonomous broad crawling;
- production scheduler/continuous observation (EB-07);
- subscriber-visible browser/product integration and production deployment (EB-08);
- graph DB, vector DB, Kafka or agent framework;
- sale probability, lead score or CRM semantics.
